# 検査画面の使い方

[ドキュメント一覧](README.md)

## 検査基準と正解画像の登録

1. Controlで本体を起床させ、撮影姿勢を整える。白や灰色の無地の台に対象を1個置く。
2. 「新しい検査基準の名前」を入力し「基準を作成」。検査範囲を調整し「設定を保存」。
3. 「正解画像（複数選択可）」で画像を選び「選択した画像を登録」。異なる正常品画像を8枚以上、推奨12〜20枚登録する。画角・距離・倍率・背景・照明を検査時とそろえる。
4. 必要に応じて「カメラ画像を正解として登録」で画像を追加する。登録した画像は一覧で確認できる。
5. 「保存した検査基準」で使う基準を選び、検査品を置いて「検査を開始」。履歴には基準名・IDも記録する。
6. 学習に使っていない画像や配置で正常品・基準外品を評価する。最初は判定時の動作を無効にして確認する。

JPEG・PNG・WebPの静止画に対応。1枚10MB以下・2400万画素以下、1回20枚・合計50MBまで。画像の向きを整え、メタデータを除いてJPEGとしてMacに保存する。重複・破損・検査範囲外など、登録できない画像はファイルごとに理由を表示する。読み込みにはカメラの接続は不要。検査には実機映像が必要。

基準を切り替えると、その基準の検査範囲・閾値・正解画像でAIを読み直す。基準名の変更で画像は失われない。検査範囲を変えると、その範囲に対応した画像が必要になる。以前の画像・履歴は保持し、範囲を戻すと再利用できる。大きく異なる撮影条件は別の検査基準として登録する。

基準が未選択、正解画像が8枚未満、カメラ未接続、撮影位置の復帰が必要な状態では、画面から検査を開始できない。画像が不足した状態でAPIから検査した場合はREVIEWとなり、AI推論は未実行として記録する。

LEGOで確認する場合は、長い赤2×8全体が余白付きで収まる画角・検査範囲を先に決め、同じ条件で赤2×4の画像を登録する。検査する種類ごとに範囲や倍率を変えない。

現在の対象抽出は彩度を使うため、赤・青など色のある対象1個に対応する。白・黒の対象、強い反射、複数の対象、背景と同色の対象、細かな傷・割れの検出は未対応。形状の比較には縦横比・投影面積などを使い、スタッド数は直接数えない。

## 判定音

「判定音（Reachy）」をONにすると、検査後に本体スピーカーで短い電子音を鳴らします。初期値はONで、OFFへの変更も再起動後に保持します。首のリアクションとは独立しています。

- OK：上がる2音、NG：下がる2音、REVIEW：同じ高さの3音。
- 「試す判定音」を選んで「音を試す」で試聴。検査履歴や正常品登録は増えず、頭部も動かしません。
- 音量はReachy Mini Controlのスピーカー設定で調整。デモモードでは本体から音を出しません。
- 本体の既存SDKメディア接続から波形を再生します。音声ファイル・外部サービスは不要。再生失敗も結果に記録し、検査画像・AI判定は保存します。
- 「判定音を送信」はSDKへの送信完了です。実際に聞こえたことは試聴で確認してください。

## 動作と停止

正常品を登録した画角で「今の撮影位置を記憶」を押すと、頭部と胴体の実測位置・7個のモーター角度を本体に保存します。再起動しても保持します。続いて実機の周囲を確認し「Reachyのリアクション」をONにします。位置が未記憶の場合は、有効化時の位置を記憶します。以後は保存した位置を中心に動き、途中でずれた位置を新しい戻り先として上書きしません。

「撮影位置へ戻す」は、リアクションOFFのままでも一度だけ復帰できます。Controlで本体を起床させ、周囲を確認してから操作してください。位置を記憶し直しても正常画像の再登録は自動では行いません。撮影条件を変更した場合は対応する正常画像を登録してください。

- OK：pitch +8° → −4° → 基本姿勢
- NG：yaw −10° → +10° → −6° → 基本姿勢
- REVIEW：roll +9° → 基本姿勢
- リアクション各区間0.8秒、復帰1秒、`minjerk`。胴体の角度も保存値を明示して固定。公式Applicationsからの起動でも自動胴体追従・音声連動の揺れ・顔追従を無効化。
- 復帰は記憶した7個のモーター角度への1秒の最小躍度補間。各モーターの実測差が0.35°以下で2回連続して安定したら撮影を許可。指示と実測の差は最大2回補正する。1回の補正は各モーター2°以内、保存角度からの指示補正の合計は6°以内。撮影位置の実測角度は上書きせず、補正済みの指示角だけを別に保持する。復帰を確認できない場合は検査を止める。
- SDK 1.12.0の`_goto_joint_positions`と`_set_joint_positions`を復帰に限定して使用。内部APIのためSDK更新時は互換性を再検証する。リアクションは公開APIの`goto_target`を使用。推定頭部姿勢から関節角を再計算し続けることで起きる復帰ずれを避ける。
- 基本姿勢が回転25°超・平行移動25mm超なら動作有効化を拒否。

撮影→画像固定→AI推論→記録→判定音→リアクション→基本姿勢→静止待ちの順で処理します。並行検査は拒否し、古いカメラ画像は使用しません。停止ボタンは動作を無効化しますが、SDKで実行中の1区間は完了してから停止します。ハードウェアの緊急停止ではありません。途中停止・復帰失敗・外部からの姿勢変更では撮影・検査を保留し、周囲を確認して「撮影位置へ戻す」で復帰するまで再開しません。停止操作後は自動で新しい復帰動作を追加しません。ライブ映像は位置合わせのため表示を続けます。

画面からの状態確認が30秒途切れると本体の動作許可が失効します。カメラ切断・SDK例外時も動作を無効化します。カメラ取得は継続を試みますが、daemon再起動でSDK接続自体が失われた場合はControlからアプリを再起動してください。再起動後は再びOFFです。

アプリ正常停止時は、動作が有効かつ接続中なら基本姿勢へ戻ります。切断時やモーションOFF時はアプリから新規動作を送りません。Control/daemon自身が行う起動・終了姿勢制御は公式側の挙動です。

## 記録と評価

全結果をSQLiteに保存し、画像を `images/` に保存します。検査ID、UTC時刻（画面はローカル時刻）、識別名、判定、理由、スコア、生のSVM判定値、推論実行有無、推論時間、モデルID、画像ハッシュ、設定、検査基準のIDと名称、動作結果、判定音の送信結果を記録。正常品の特徴もJSONで保持して起動時にモデルを再学習し、pickleはロードしません。

履歴で人が正解OK/NGと条件（照明・配置）を入力できます。

- 正解率 = 正解した件数 / 正解ラベル付きの全件数（REVIEWも分母に含む）
- 正常検出率 = OKと判定した正常品 / 正常品数
- 異常検出率 = NGと判定した異常品 / 異常品数
- 見逃し = 異常品をOKと判定した件数
- 誤排除 = 正常品をNGと判定した件数（APIの `false_rejects`）
- 判定率 = REVIEW以外 / 全評価件数（APIの `coverage`）

CSVには画像ファイル名・設定・モデルID・正解を含めます。画像を共有する場合は対応するJPEGも一緒にコピーしてください。先頭の `= + - @` 等はCSV式として実行されないようエスケープします。
